Permissions

Five permissions and one optional one. Each is here with what it is for, what it lets the extension do, what it does not, and Chrome's own description of it, fetched from developer.chrome.com on 24 October 2026. Chrome's documentation changes; the links go to the current page.

The manifest, as shipped. "permissions": ["activeTab", "scripting", "storage", "contextMenus", "sidePanel"] and "optional_host_permissions": ["https://*/*", "http://*/*"]. No host_permissions. The validator rejects a build whose manifest says anything else.

activeTab

Why: so that clicking the icon, pressing the shortcut or choosing the context menu item lets the extension change the tab you did it on, and no other.

Chrome says (the activeTab permission): it "gives an extension temporary access to the currently active tab when the user invokes the extension". "Access to the tab lasts while the user is on that page, and is revoked when the user navigates away or closes the tab." The gestures that grant it are "Executing an action", "Executing a context menu item", "Executing a keyboard shortcut from the commands API" and "Accepting a suggestion from the omnibox API". "The extension temporarily gets host permissions for the tab's main frame origin." It "displays no warning message during installation". "Access is not granted to restricted pages, such as chrome:// pages."

Cannot: touch a tab you did not invoke it on; keep access after you leave the page; reach a cross-origin frame inside the page; reach Chrome's own pages.

scripting

Why: to put the engine (engine.js) on the page. On demand, through chrome.scripting.executeScript into the tab the activeTab grant covers. Persistently, through chrome.scripting.registerContentScripts for an origin you have granted, and unregisterContentScripts when you remove it.

Chrome says (chrome.scripting): "By default, an injection will run in the main frame of the specified tab." Files "are specified as strings that are paths relative to the extension's root directory", so only bundled files can be injected. Registered scripts' persistAcrossSessions "specifies if this content script will persist into future sessions. The default is true." The API needs either host permissions or activeTab for the pages it touches.

Cannot: by itself reach any page. It runs only where activeTab or a granted origin allows, and only files from the package.

storage

Why: to keep your rules, in chrome.storage.local under one key, rules. The options page reads and writes it; the engine reads it and listens for changes so a disabled rule lets go of the title at once.

Chrome says (chrome.storage): storage.local has QUOTA_BYTES of 10485760 bytes, about 10 MB. storage.sync is about 100 KB in total and 8 KB per item; this extension does not use it.

Cannot: see any site's storage, cookies or data. The extension's storage is its own, inside your Chrome profile, and is deleted when the extension is removed.

contextMenus

Why: one item on a page's right-click menu, "Set this tab's title…", as a second way in. Chrome counts "executing a context menu item" among the gestures that grant activeTab, so it reaches the same tab the click was on.

Chrome says (chrome.contextMenus): the API adds items to Google Chrome's context menu. It carries no access to page content.

Cannot: read anything about the page. The item knows only that it was clicked, and in which tab.

sidePanel

Why: so the playground can open beside the page it works on, in Chrome's side panel, and stay there while you browse.

Chrome says (chrome.sidePanel): "To use the Side Panel API, add the "sidePanel" permission in the extension manifest file." The panel's page is set by side_panel.default_path. sidePanel.open() "may only be called in response to a user action", which here is the button in the popup or the context menu item. "The side panel remains open when navigating between tabs." "As an extension page, side panels have access to all Chrome APIs", which means the same APIs as the popup, no more: a page in the panel sees a tab only when activeTab or a granted site allows it.

Cannot: see or touch a page by itself. It is a place for the extension's own page to live; what that page may do is set by the other permissions.

optional_host_permissions: https://*/* and http://*/*

Why: so that "Always on this site" can ask Chrome for one origin at the moment you tick it. These are declared as optional, which means nothing under them is granted at install.

Chrome says (chrome.permissions): "If you want to request hosts that you only discover at runtime, include "https://*/*" in your extension's optional_host_permissions field." "Permissions must be requested from inside a user gesture, like a button's click handler." permissions.remove() "removes access to the specified permissions", and the options page's Remove access button calls it.

Cannot: be granted without your yes, in Chrome's own prompt, for a specific site. The extension asks for exactly the origin of the page you are on (or the wider pattern you typed, after a confirmation). Every granted origin is listed on the options page with a Remove button.

What it does not ask for

PermissionWhat it would allowWhy not here
host_permissions, <all_urls>Standing access to sites, from installThe one rule. Access is per site, after you ask, and revocable.
tabsThe URL and title of every tab, all the timeNot needed: activeTab gives the URL and title of the tab you invoked it on, while you are there.
history, cookies, webRequest, debuggerYour history, your cookies, your traffic, a debugger on the pageNone of it has anything to do with a title. The validator rejects a manifest that names them.
userScriptsRunning code the user writesA different product. Chrome's documentation says "Users must enable developer mode to execute anything" with it; this extension runs only its own bundled code.

The Content Security Policy

The extension's own pages (the popup and "My rules") run under script-src 'self'; object-src 'self'; connect-src 'none'. The first two mean only scripts from the package can run there. The last, connect-src 'none', is the no-network rule made into a browser barrier: the pages cannot open a connection to anything, not even to the package itself. Chrome's documentation on remotely hosted code defines it as "anything that is executed by the browser that is loaded from someplace other than the extension's own files", and does not allow it in Manifest V3; this extension has none, and the validator checks the code for eval, new Function, remote scripts, fetch, XMLHttpRequest and WebSocket on every build.

fix-the-page.chrome-extension.sgit.ai

A Chrome extension that fixes the page you are on, only when you ask, and can say exactly what it changed. One generic extension, built on activeTab, starting with the tab's title. Code Apache 2.0; content CC BY 4.0.

Published by the sgit project. The extension makes no network calls and sends nothing anywhere; this site is static and has no analytics.
