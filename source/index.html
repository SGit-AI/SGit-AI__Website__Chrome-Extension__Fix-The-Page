Source and releases

The article this extension comes from says such an extension "could be shipped from a GitHub repository or an encrypted vault and loaded locally, so the reader can see exactly what they are installing". So: the whole extension is a dozen small files with no dependencies, readable in one sitting, and every release is a zip of exactly those files with its hash published here.

To check a download: shasum -a 256 fix-the-page-v0.3.0.zip (macOS, Linux) or certutil -hashfile fix-the-page-v0.3.0.zip SHA256 (Windows) and compare with the hash above. The zip is built by admin/build/package.mjs from extension/, and the validator refuses a release whose zip differs from extension/ in any byte, or whose hash file does not match. The site's version, the extension's version and the zip's name are one number: the release history has them all.

The extension, file by file

FileWhat it does
manifest.jsonManifest V3. The five permissions, the optional host permissions, the CSP, the sandbox page, the popup, the options page, the side panel, the shortcut. Explained here.
engine.jsThe one script that touches a page. Half of it is pure functions with no DOM: parse a match pattern, match a URL, compute a title from a rule, validate a rule, validate an import file. Node tests them without a browser. The other half applies rules to document.title, watches the <title> element and the URL, and undoes. Injected both on demand and as a registered content script; idempotent either way.
bridge.jsRuns in the page's own world for one purpose: to notice a site that publishes window.__tools.page and leave its name and version on an attribute the engine can read. Twenty lines.
service-worker.jsKeeps the registered content scripts in step with the origins you have granted, answers the popup and the options page, and adds the context menu item. Makes no network calls, never reads a page.
popup.html, popup.js, popup.cssThe toolbar popup: the page's title and URL, the title field, the mode, the pattern, Apply, Always on this site, Undo. Says when Chrome does not allow it on a page.
options.html, options.js, options.css"My rules": rules by site, sites with access, export, import, the build stamp.
build.json, build.jsThe build stamp: version, git commit, build time. Written by package.mjs; shown in the options page footer.
icons/Three PNGs, drawn by admin/build/icons.mjs, no image editor involved.

No framework, no build step for the extension itself: what is in extension/ is what runs. Browse it on GitHub.

The validator: what a release must pass

node admin/build/validate.js runs before every push and in CI, and a failure means no tag and no publish. It started as the hub's validator and adds the extension's own gates:

  • Version agreement: admin/build/version.txt, assets/version.js, every page's badge, llms.txt, index.md, the versions table, extension/manifest.json, extension/build.json and package.json all carry the same version.
  • Every internal link resolves; every canonical URL is on this host and names its own page.
  • No file in the tree looks like a key, a token or a private key.
  • The manifest: no host_permissions; no tabs, history, cookies, webRequest, debugger or <all_urls>; only the five permissions; optional host permissions for http and https only; no static content scripts; a CSP with no remote or unsafe source and connect-src 'none'.
  • The code: no eval, new Function, fetch, XMLHttpRequest, WebSocket, importScripts, sendBeacon, string timers, innerHTML assignment, inline scripts or handlers, or any URL of a remote script or stylesheet.
  • The release: the zip and its .sha256 exist for this version, the hash matches, the zip's files equal extension/ byte for byte, the zip's manifest is not a test build, and this page publishes the current hash.
  • Every page links to the current release.

The tests

npm test runs tests/run.mjs, which builds a test variant of the extension, runs every test file, and fails if a test file was not run or ran zero tests (the hub's fifth silent failure, "a test file nothing imports"). Three layers, after the brief's acceptance table:

LayerHowCovers
Engine unit testsNode, no browser, the pure coreThe match pattern grammar against many URLs and many patterns; the four modes; rule and import validation, including files with unknown fixes, bad patterns and code-like fields; export then import gives identical rules
Engine in a pagePlaywright, fixture pages, engine.js added to the page, no extensionA static page; a page that rewrites its title every 500 ms (the observer does not loop); a single-page app with pushState; template following the page's later titles; undo; injecting the engine twice; a replaced <title> element; site API detection
Extension in ChromiumPlaywright, the test build loaded unpackedA persistent rule applies at load with no click; removing a site's access unregisters the engine; the popup on a normal page and on a chrome:// page; "Always on this site"; the options page's edit, enable, delete, export, import and remove access
The validatorNodeThe shipped manifest and code pass; manifests and code written to fail are caught

Three checks are manual, because Chrome's toolbar icon and its permission prompt are browser UI that automation cannot press: a real install from the site, Chrome asking for one site only, and the popup on a Chrome page. They are done before each release that touches the popup, the permissions or the engine, and recorded in the debriefs.

The test build lists http://127.0.0.1/* in host_permissions, standing in for the per-site grant a test cannot click. It is never shipped: the validator refuses a release zip that carries it.

Building it yourself

$ git clone https://github.com/SGit-AI/SGit-AI__Website__Chrome-Extension__Fix-The-Page.git
$ cd SGit-AI__Website__Chrome-Extension__Fix-The-Page
$ npm test                          # needs Node 22 and Playwright with Chromium
$ node admin/build/package.mjs      # releases/fix-the-page-v0.3.0.zip and its .sha256
$ node admin/build/validate.js

The zip writer is deterministic: the same tree gives the same bytes, apart from the build stamp.
