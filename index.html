Fix the page you are on. Only when you ask.

One generic extension that can fix any kind of site, built on activeTab. It touches a tab only when you invoke it there, it keeps nothing it does not need, and it can say exactly what it changed. Version 0.1 ships one fix, done properly: the tab's title.

Install from the repo or the zip → The title fix → Read the source →

The one rule

The extension touches a page only because the user asked it to, on that page, and it can say exactly what it changed.Everything else follows from it: activeTab instead of host permissions, fixes as rules rather than code, per-site opt-in for persistence, a visible list of every rule and every site with access, and no network calls at all.

What version 0.1 does

Set a tab's title to a value you choose. Useful when ten tabs of the same web app all say the same thing, when a title is too long to read in a tab strip, or when a dashboard should say what it is for.

Built

Set this tab's title

Click the icon, type, Apply. The tab says what you typed, now, even on a single-page app that keeps rewriting its own title. It lasts until you leave or reload the page.

How → Built

Keep it, on one site

Tick "Always on this site". Chrome asks you to allow that one site. From then on the title is applied on every visit to matching pages, with no further clicks.

How → Built

Review, edit, undo

"My rules" lists every rule and every site with access, each with a remove button. Export and import your rules as a JSON file. Undo on any page in one click.

How → Built

Say exactly what it may touch

Five permissions, each explained with Chrome's own words. No host permissions at install, no remote code, no network. The validator in the repo refuses a build that breaks any of this.

The permissions →

New in 0.2: the playground, and a policy for every script

Write a small fix as a script, tick what it may do, run it on a page, see exactly what it did, undo it, keep it. The script runs in a sandbox with nothing in it but the capabilities you ticked, and every call is checked against the policy before it reaches the page. A fix that may only set the title cannot do anything else, whatever it says.

Built

The playground, beside the page

Opens in Chrome's side panel next to the page it works on, and follows you from tab to tab. Eight capabilities, each reversible: read or set the title, read the URL, count, read or replace an element's text, hide elements, add a stylesheet. Saved experiments live in your browser; export them as a file to share.

How it works → Article

Script Behaviour Policies

The Agent Behaviour Policy model applied to a line of JavaScript: what the script may do (the mandate), what a script on a page can do (the grant), the difference, and where each line is enforced. Static review and runtime enforcement, both.

How a fix reaches a page

Two routes, and the extension tells you which one it is using.

On demand · the default

activeTab

Chrome's documentation: the permission "gives an extension temporary access to the currently active tab when the user invokes the extension", and "access to the tab lasts while the user is on that page, and is revoked when the user navigates away or closes the tab". Clicking the icon, the keyboard shortcut and the context menu item are the gestures that grant it. Nothing is granted at install, and Chrome shows no install warning.

Persistent · per site · opt-in

optional_host_permissions

When you tick "Always on this site", the extension asks Chrome for that one origin, and Chrome shows its own prompt. If you agree, the engine is registered for that origin only and runs at page load to apply your rules. The options page lists every such site, and Remove access takes it back in one click.

What it does not do

No standing access to the web

No host_permissions in the manifest, no <all_urls>, no tabs, history, cookies, webRequest or debugger. The validator rejects a manifest that asks for any of them.

No code from anywhere else

Rules are data: a rule names a bundled fix and a value, and the bundled engine interprets it. The playground runs your own scripts, in a sandbox with no network and no page, and only when you press Run. Nothing is fetched, nothing from an import file is executed, and no script runs without you.

No network, no telemetry

The extension's own pages run under a Content Security Policy with connect-src 'none'. The validator refuses any fetch, XMLHttpRequest or WebSocket in the code. Rules live in your browser; export and import go through files you choose.

Nothing of the page but what the fix needs

It reads the URL, to match rules, and the title, to replace it. It never reads form fields, cookies or page text, and never stores them.

Where this comes from

The newsroom article Fix the page yourself (17 October 2026) argues that the next user experience is the one the user customises, prefers fixes "the reader is the one who clicks" for, and says plainly that its author does not like "one extension with access to every site I visit". This extension reconciles the two: generic in what it can do, narrow in what it may touch at any moment. It is a child of the chrome-extensions.sgit.ai hub and follows its guides, including the one on build provenance: the options page shows the version, the commit and the build time, because "running an old build" is the hub's first silent failure.

After the playground

A proposed order, none of it started without Dinis's word. Each would be a release of its own. The plan has the detail.

Proposed

Saved fixes that run on their own

An experiment you keep, applied at load on a site you have granted, under its policy, with the same undo. Needs the sandbox to run without the playground open.

Proposed

The extension in its own repository

Its own tests, releases and version; this site stays the page and states which release it serves.

Proposed

A library of fixes, with contributors

One folder per fix: the script, its policy, a README that says the same thing, tests on a fixture page, a review record. Generic fixes and site-specific ones, side by side.

Out of scope by design

Scripts with the run of the page

A userscript manager gives a script everything the page can do. Here a script gets what its policy says, enforced outside its reach, or it does not run.

Status marks on this site: built is in this release and tested; specified is written down in the brief and not yet built; proposed is an idea for Dinis to accept or refuse.
