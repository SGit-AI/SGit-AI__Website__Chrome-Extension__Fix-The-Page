## What shipped: v0.2.0

**The playground** (`extension/playground.*`). Opened from the popup for the tab it was clicked on. A script (the body of an async function over `page` and `log`), a policy (tick boxes for eight capabilities, limits on calls and time), a match pattern that marks the experiment generic or site-specific, a static review that updates as you type, Run, Undo this run, Undo every run, Save, Export, Import, Copy as JSON, seven starter examples. Experiments live in `chrome.storage.local` under `experiments`.

**The Script Behaviour Policy core** (`extension/sbp.js`, pure, tested in Node). `validatePolicy`, `checkCall` (the gate), `lintScript` (calls versus grants, unused grants, banned names with line numbers), `validateExperiment`, `validateExperimentsFile`, `exportExperiments`. Policy shape: `{ policy: "fix-the-page/sbp", version: 1, capabilities: [...], limits: { calls, ms }, selectors?: [...] }`.

**The sandbox** (`extension/sandbox.html`, `sandbox.js`). Declared under the manifest's `sandbox` key, so Chrome gives it an opaque origin and no extension APIs; a CSP of `sandbox allow-scripts; script-src 'self' 'unsafe-eval'; connect-src 'none'` and nothing else allowed. It builds a `page` object from the granted capabilities, builds the script with `new Function` with the usual globals shadowed, runs it under a timer, and turns every capability call into a `postMessage` to the playground. The playground accepts messages only from the sandbox frame and checks each against the policy; refusals are written in the run log.

**Capabilities in the engine** (`extension/engine.js`): `title.get`, `title.set` (as an ephemeral title rule, so it is held against rewrites), `url.get`, `dom.count`, `dom.text`, `dom.hide`, `dom.setText`, `css.add`; argument checks of its own; an effects log per run; `undoRun` reverses in reverse order; `undoAllRuns`; `runEffects` for the log. Messages: `ftp:cap`, `ftp:cap-undo`, `ftp:cap-effects`.

**The validator**: comments and string literals are blanked before the code bans run (a list of banned names may name `fetch`); `new Function` is allowed in `sandbox.js` alone, by name; an `<iframe>` may only point at a declared sandbox page and must carry a `sandbox` attribute; a sandbox CSP must set `connect-src 'none'`, start with `sandbox allow-scripts;` and allow nothing else.

**The tests**: 214 in all, green locally. New: 45 for the policy core; 5 capability tests in a page; 8 tests of the sandbox realm as a plain page under its CSP, including the escape through `(async () => {}).constructor`, which reaches the sandbox's own empty window and a `fetch` the CSP refuses; 5 playground tests in Chromium (run and undo, static refusal, forged message ignored, banned word, save/export/import/delete). The test server now serves `extension/` at `/ext/` so the sandbox can be loaded without the extension.

**The site**: the article *Script Behaviour Policies: a behaviour policy for a line of JavaScript* with the ABP → PBP → SBP mapping, the barrier table, the layers, static and runtime enforcement, the worked example, what fits in eight verbs, the community shape, what it does not claim; an articles index; the playground page; the plan to split the extension from the site and start a library of fixes (`admin/plans/`); the home page and navigation; `llms.txt`, the sitemap, the README; a playground screenshot.

## Decisions taken, for Dinis to confirm or overturn

1. **Scripts are in, under a policy.** v0.1's position was "fixes are data, arbitrary JavaScript is out of scope". Dinis asked for a playground for scripts and a policy that limits them. The reconciliation: a script runs only in a realm that holds nothing but the granted capabilities, with the gate outside its reach. The one rule stands: the extension touches a page only because the user asked, on that page, and the run log says exactly what it changed. The roadmap text on the site was changed accordingly, and this debrief records the change.
2. **The gate is in the playground, not the sandbox.** The sandbox's shadowing is a convenience; the test suite escapes it on purpose to show it gains nothing. The policy check happens in a realm the script cannot script.
3. **Eight verbs, no more, for now.** Each verb is bounded and reversible. Inserting markup, navigation and calling a site's page API are each a verb with its own argument rules, and are proposed, not built.
4. **Experiments do not run on their own.** Saved experiments run when Run is pressed with the playground open. Running them at load on granted sites needs the sandbox to run without the playground (an offscreen document, probably) and is in the plan.
5. **One repository still.** The split is planned, not done: it is Dinis's call on names, and it is cleaner to do it from a release that already works.
6. **Version numbering.** v0.2.0 for both site and extension, as the pipeline expects; the plan decouples them after the split.

## What failed, and why

- `eval` cannot be a parameter name in strict code, so the first sandbox build threw a syntax error on every run. Removed from the shadow list; a direct `eval` inside the script still sees only the shadowed scope, an indirect one reaches the empty sandbox window.
- The first escape test used `F('return this')()` on an async function constructor: `this` is undefined in strict code and the result is a promise. Fixed to `await F('return globalThis')()`.
- The validator flagged the words `XMLHttpRequest`, `WebSocket` and `EventSource` in the banned-names lists of `sbp.js` and `sandbox.js`. The bans now run on code with strings and comments blanked; the remote-URL check still runs on raw text.
- A test compared `innerText` with a label the CSS uppercases.
- The Chrome page on sandboxing eval at `/develop/concepts/sandboxing-eval` returned 404; the manifest `sandbox` reference was used instead.

# Later the same day: v0.3.0, the playground beside the page

Input: Dinis set up the domain as `fix-the-page.chrome-extension.sgit.ai` (singular) and the site is live there; he wants the playground side by side with the page, as his LinkedIn Activity Recorder extension does it (three screenshots, for reference only, not published: its popup with a version pill, a status, a big "Open panel" button and "Open in tab"; its side panel staying open while browsing). That extension is deployed through sgit vaults, noted for the plan's distribution route.

## What shipped

- **The playground is the side panel.** `sidePanel` permission and `side_panel.default_path: playground.html`. Opened from a button in the popup (`chrome.sidePanel.open({ tabId })` in the click handler, since Chrome says it "may only be called in response to a user action") or from a context menu item. In panel mode the playground follows the active tab it is allowed to see (`tabs.onActivated`, `tabs.onUpdated`, `windows.onFocusChanged`); a tab it may not see gives a message saying what to click. Undo remembers which tab each run was on. "Open in a tab" keeps the bound, full-page form, which the tests use.
- **The popup** gained a version pill and the panel block, in the recorder's shape.
- **The domain** changed everywhere: CNAME, canonicals, manifest `homepage_url`, the twins, llms.txt, the sitemap, the README, the generator. The 24 October debrief keeps the old name as history.
- **The validator** allows `sidePanel` (a UI permission with no page access) and checks `side_panel.default_path` is a local file. The site's permissions page explains it with Chrome's words.
- **Tests:** 216 green locally. A panel-mode test switches the active tab from the service worker and checks the panel re-binds, runs, says "no page" on a chrome:// tab, and still undoes on the old tab.

## Decisions, for Dinis

1. The fifth permission. `sidePanel` carries no access to pages; Chrome shows no warning for it. Rule 1 of the policy named four permissions; this is the one change, recorded here and on the permissions page.
2. The panel sees a tab only after the icon was clicked on it, or on an allowed site. That is the one rule holding: a `tabs` permission would let the panel read every tab's URL and title, and the validator still refuses it. The cost is one extra click per new tab; "Always on this site" removes it for a site you work on often.

## What failed

- The panel test undid to "[edited] Original" because an earlier test leaves a stored prefix rule, which the engine the playground injects applies. The test now clears rules first; the behaviour is correct.
- `sed` could not change the brand name split across a `<span>`; the generator was changed and every page regenerated.
