## What shipped: v0.1.0, the first MVP

**The extension** (`extension/`, Manifest V3, no dependencies, 15 files, 55 KB unpacked):
- `engine.js`: a pure core (match-pattern grammar, `matchRule`, `computeTitle`, `validateRule`, `validateImport`) and a page part that applies rules to `document.title`, holds the title against rewrites with a `MutationObserver` on `<head>` (and on `<html>` for a replaced `<title>` or a head that does not exist yet at `document_start`), re-evaluates on `popstate`, `hashchange` and a once-a-second URL check (pushState fires no event), undoes, and is idempotent. The four modes: `set`, `prefix`, `suffix`, `template`.
- `bridge.js`: detects a site's `window.__tools.page` from the main world and leaves name, version and fix names on a data attribute. v0.1 only detects; the popup says so.
- `service-worker.js`: reconciles registered content scripts with granted origins (idempotent, on install, startup and permission changes), answers register/remove/list messages, adds the context menu item which, being an activeTab gesture, injects the engine then tries `action.openPopup()`.
- Popup with live preview, editable match pattern (refused if it does not match the page; confirmed if wider than one origin), Apply, Always on this site (permission request from the click, then store, then register; the engine applies via the storage change, so nothing double-applies), Undo, the restricted-page message. `?tabId=` is accepted for the automated tests.
- Options page: rules grouped by origin with edit/enable/delete, sites with access with Remove, export (download) and import (validated whole), build stamp and shortcut.
- Shortcut: `_execute_action` on Alt+Shift+T, so Chrome opens the popup and grants activeTab with no code of ours.

**The release:** `releases/fix-the-page-v0.2.0.zip` and `.sha256`, built by `package.mjs` with a dependency-free deterministic zip writer (`admin/build/zip.js`). `package.mjs` also stamps `build.json`/`build.js`, re-points every page's release link, and writes the hash into the source page. `--test` builds the test variant with `host_permissions` for 127.0.0.1 and localhost.

**The validator:** the hub's, minus its blocklist, plus: manifest within ABP rule 1; code within rules 2 and 3 (also `importScripts`, `sendBeacon`, string timers, `innerHTML`, inline scripts and handlers, remote URLs); the zip equals `extension/` byte for byte, is not a test build, and its hash is published; every page links to the current release; version agreement across site, manifest, build stamp and package.

**The tests** (all green locally): 97 engine unit tests, 11 engine-in-a-page tests, 12 extension-in-Chromium tests, 31 validator tests. `tests/run.mjs` fails if a test file is not run. Acceptance table: A1 to A12 automated. A13 to A15 are manual and **not yet done**: this session has no real Chrome with a toolbar to click. Dinis's first install is that check.

**The site:** home, install (clone first, zip second, screenshots from the test build and the real build), the title fix, permissions (Chrome's documentation fetched and quoted), privacy, source and releases, versions, how this site is built; markdown twins; llms.txt, robots.txt, sitemap.xml; the hub's stylesheet with a few additions; the hub's pipeline with a test job added.

## Decisions taken, for Dinis to confirm or overturn

1. **Domain:** `fix-the-page.chrome-extensions.sgit.ai`, as the pack assumed (plural, under the hub's domain). The repository description says `chrome-extension` singular. The CNAME file carries the plural; no DNS exists yet, so changing it is one line.
2. **Shortcut:** `_execute_action` (open the popup) rather than a named `set-title` command. Same key, same effect, less code.
3. **Pattern wider than one origin:** allowed after a confirm dialog, and Chrome then asks for all of it. The pack said "reject unless the user confirms"; this is that.
4. **Several rules on one URL:** they chain in creation order (a `set` then a `suffix` does what it says), rather than last-wins.
5. **Export/import merge:** import replaces rules with the same id and adds the rest, so re-importing your own export is a no-op and a fresh profile gets identical rules (A8).
6. **The test job in CI:** added to the hub's pipeline, between validate and tag. It needs Playwright and Chromium on the runner, about two minutes.
7. **Pushed to `claude/trusting-hamilton-vpkbl4`,** the branch this session was given, not to `dev`. The pipeline runs on `dev` and `main`; merging (or pushing) to `dev` is what releases v0.1.0. The commit subject carries `site v0.1.0:` so the tag job will find it.

## What failed, and why

- Three browser tests failed on first run: a wrong fixture expectation (the SPA's static title), a Playwright identity comparison that can never be true across serialisation, and a real engine bug: a title the page set while no rule was active was not recorded as the page's own, so `template` built on a stale value. Fixed by refreshing the page's own title whenever the engine is not holding it.
- Six extension tests failed on first run from one cause: a failed test left its tab open, and `tabs.query` picked the stale tab. Content-script globals are also invisible to `page.evaluate` (isolated world), which the tests now respect by asking the engine through `tabs.sendMessage`. The test build's two required origins made "no registrations left" the wrong assertion; the tests now check the one origin.
- `removeSite` in the service worker called `reconcile()` after removing, which in the test build re-registered the required origin at once. Removed; the real build gets the same effect from `permissions.onRemoved`.
- The repository's `.gitignore` is a Python template that ignores `build/`, which would have silently dropped `admin/build/`. A negation was added.
