How this site is built

For the agent that maintains this repository, and for anyone checking its work. The site is static HTML on GitHub Pages; the extension is the extension/ folder; one pipeline validates, tests, tags and deploys both.

The agent and its policy

This repository is maintained by a dedicated Claude Code session, fix-the-page.dev, under an Agent Behaviour Policy written in the briefing pack of 24 October 2026. In short: push only to this repository's release branch; read the hub and the newsroom but never push to them; activeTab is the only standing access; no remotely hosted code; no network calls from the extension; read nothing from a page but what a fix needs; never commit a secret; version everything; never push a red build; cite Chrome's documentation for every fact about Chrome; British English, no em-dashes, no superlatives about our own work; contact nobody. Dinis Cruz is the editor and owner, and when the pack and Dinis disagree, Dinis wins.

The pipeline

.github/workflows/deploy-pages.yml, copied from the hub with one job added. On every push to dev:

  1. validate: node admin/build/validate.js. A failure stops everything.
  2. test: node tests/run.mjs, with Playwright and Chromium installed on the runner.
  3. tag-release: reads admin/build/version.txt, finds the release commit (site vX.Y.Z: …), checks the two agree and that the bump is the next minor (or a deliberate major), and pushes the tag.
  4. deploy: publishes the tree to GitHub Pages.

The release recipe

$ git pull --ff-only origin dev
# bump admin/build/version.txt once; set extension/manifest.json and package.json to match
$ node admin/build/package.mjs        # stamps build.json, builds the zip and .sha256, re-points the pages
$ npm test
$ node admin/build/validate.js
# add a row to admin/versions.html; write admin/debriefs/YYYY-MM-DD.md
$ git commit -am "site vX.Y.Z: what changed"
$ git push origin dev

What needs a human

  • DNS: a CNAME record for fix-the-page.chrome-extensions pointing at GitHub Pages.
  • GitHub Pages: enabling it on the repository, and allowing dev in the github-pages environment.
  • The Chrome Web Store: any publication there. Not in v0.1.
  • The three manual acceptance checks before a release that touches the popup, the permissions or the engine; see the tests.

Debriefs

One per working session, in admin/debriefs/: what shipped, what failed and why, what is next. The next session reads the latest one first.
